# Сервис: WintimeService (Client)

## 1. Описание

**`WintimeService`** — история статусов WinTime **текущего** дистрибьютора
(из контекста авторизации) **этапами**: каждая смена состояния (регистрация,
бан/разбан, активация/истечение пакета дерева) с пересчётом пассивного дохода —
сколько заработано на каждом этапе и какой накопленный баланс был к его концу.
Плюс **второй список доходов** — разовые бонусы за личные приглашения (из
финансовых транзакций леджера) — и **общая сумма доходов**.

Назначение — прозрачность начислений: по таймлайну этапов видно, когда и почему
менялась скорость дохода и как рос баланс.

## 2. Метод

`GetMaskHistory(google.protobuf.Empty)` → `MaskHistoryResponse { total_income, passive_items[], referral_items[] }`.

Ответ — **полная** история в хронологическом порядке (старые → новые), **без
пагинации**: смены статуса по природе редки (десятки записей на дистрибьютора).
Последний элемент — текущее состояние.

`MaskHistoryResponse.PassiveItem` (один этап личного пассива):

| Поле | Значение |
|---|---|
| `ts` | Момент смены статуса (бизнес-дата события). |
| `flag_account_active` | Аккаунт активен: зарегистрирован и не забанен. |
| `flag_tree_lite_active` | Активный слот в ПЕРВОМ дереве (Lite). |
| `flag_tree_pro_active` | Активный слот во ВТОРОМ дереве (Pro). |
| `multiplier` | Множитель скорости пассивного дохода для этого состояния (серверная LUT). |
| `earned` | Начислено ЗА этот этап: полные минуты интервала от этой смены до следующей (у последнего — до текущего момента) × `multiplier`. Интервал отсчитывается от максимума из {момент смены, регистрация, старт пассивного дохода} — та же арифметика, что у фактического начисления. |
| `accumulated` | Накопленный пассивный доход к КОНЦУ этапа (нарастающий итог; у последнего — накоплено на текущий момент). |

Пересчёт в `items` покрывает **только собственный пассивный доход**; доходы за
личные приглашения идут отдельным списком, прочие дискретные начисления в
леджер (квесты, корректировки) в ответ не входят.

`MaskHistoryResponse.ReferralItem` (доход за личное приглашение):

| Поле | Значение |
|---|---|
| `ts` | Момент начисления бонуса. |
| `child_distributor_id` | Личник, за которого начислен бонус. |
| `amount` | Начислено WinTime (базовая ставка × множитель на момент начисления). |
| `accumulated` | Накоплено за приглашения к этому начислению включительно (нарастающий итог; у последнего — суммарный доход за все приглашения). |

Итоговые поля ответа:

| Поле | Значение |
|---|---|
| `total_income` | ОБЩИЙ доход со всех источников ниже: накопленный пассив (`accumulated` последнего этапа) + доход за приглашения (`accumulated` последнего начисления). Идёт первым — при добавлении новых видов бонусов списки дописываются после. |
| `passive_items` | Этапы личного пассивного дохода (хронология, полный список). |
| `referral_items` | Доходы за личные приглашения (хронология, полный список; источник — транзакции леджера с reason `WinTimeReferral`). |

## 3. Права доступа

Session-токен с `Permission::WINTIME_VIEW` (входит в стандартный набор прав
пользователя). Только свои данные; произвольный дистрибьютор — админский
`biconom.admin.wintime.WintimeAdminService` (сырой журнал для диагностики).
