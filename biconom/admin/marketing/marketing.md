# Сервис: MarketingService (Admin)

## 1. Описание

**`biconom.admin.marketing.MarketingService`** предоставляет административный интерфейс для управления маркетинговыми активностями, лицензиями и слотами. В отличие от клиентского API, методы здесь доступны только сотрудникам компании с соответствующими правами.

## 2. Методы API

### `GrantSubscription`
- **Назначение**: Позволяет администратору "подарить" (выдать бесплатно) подписку или лицензию конкретному слоту или дистрибьютору. Технически это эквивалентно покупке пользователем пакета, но списания средств не происходит (оплачивается "Компанией").
- **Входные параметры**:
    - `plan_id`: Идентификатор тарифного плана (`license_id` + `license_entity_id`).
    - `target`: Цель назначения — либо конкретный `slot_id`, либо `distributor_id`.
    - `admin_comment`: Примечание для логов аудита.
- **Возвращаемое значение**: Обновленный объект `MarketingSlot` с актуальным состоянием лицензии.

### `SetDistributorParent`
- **Назначение**: Меняет вышестоящего (спонсора) у конкретного дистрибьютора. Дистрибьютор вместе со всем своим поддеревом переезжает под нового спонсора в **дереве спонсорства**.
- **Входные параметры**:
    - `distributor_id`: ID переносимого дистрибьютора (> 0).
    - `new_parent_id`: ID нового спонсора (> 0).
- **Возвращаемое значение**: Позиция дистрибьютора после переноса — `prev_parent_id`, `parent_id`, `level`, `network_partition_id`, `structure_quantity`.
- **Что метод делает**: запись в историю смены спонсора, пересчёт уровней всего поддерева, счётчиков структуры (`structure_quantity`, `structure_level_max`) у обеих линий предков, перенос партиции сети, перенос объёмов стейкинга ветки и счётчиков стейкеров.
- **Чего метод НЕ делает** (осознанные ограничения контракта):
    - **Маркетинговые деревья (слоты) не двигаются.** Спонсорство и расстановка слотов — разные структуры; после переноса они расходятся штатно.
    - **История начислений задним числом не пересчитывается.** У выплаченных бонусов глубина зафиксирована в проводке — старые начисления продолжат показывать прежнюю линию.
    - **Реферальная привязка WinTime не меняется.** Она фиксируется один раз при регистрации; реф-доход на нового спонсора не переносится.
- **Откат**: отдельного метода нет — откат делается повторным вызовом с `prev_parent_id` из ответа. Оговорка: если дистрибьютор был корнем собственной партиции сети (`prev_parent_id = 0`), при переносе эта партиция архивируется и обратным вызовом не восстанавливается.
- **Идемпотентность**: повторный вызов с тем же `new_parent_id` — не ошибка. Метод возвращает текущее состояние и дерево второй раз не трогает (записи в историю не будет).
- **Ошибки**:
    - `DISTRIBUTOR_NOT_FOUND` — `INVALID_ARGUMENT` при нулевом аргументе, `NOT_FOUND` если дистрибьютора или нового спонсора не существует.
    - `DISTRIBUTOR_PARENT_SELF` — `INVALID_ARGUMENT`, `distributor_id == new_parent_id`.
    - `DISTRIBUTOR_PARENT_CYCLE` — `FAILED_PRECONDITION`, новый спонсор является потомком переносимого. Метод сознательно НЕ перевешивает мешающее поддерево автоматически: что двигать первым — решает администратор.
    - `DISTRIBUTOR_NETWORK_MISMATCH` — `FAILED_PRECONDITION`, новый спонсор из другой сети.

## 3. Права доступа и безопасность
- Требуется роль администратора (например, `MARKETING_ADMIN` или `SUPER_ADMIN`).
- `SetDistributorParent` требует `Permission::ROOT` — операция необратимо меняет структуру сети.
- Все действия логируются в Audit Log с указанием `admin_comment`.
- Факт смены спонсора хранится в `distributor_parent_history`: дистрибьютор, прежний и новый родитель, прежняя и новая партиции, момент операции.

## 4. Сценарии использования
- **Подарок от компании**: Начисление приветственного пакета топ-лидерам при старте.
- **Компенсация**: Выдача лицензии в качестве извинения за технические сбои.
- **Тестирование**: Выдача лицензий тестовым аккаунтам для проверки механик маркетинга.
- **Исправление ошибочной регистрации**: Партнёр зарегистрировался не под тем спонсором — `SetDistributorParent` переносит его вместе с уже набранной структурой.
