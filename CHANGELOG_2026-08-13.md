# CHANGELOG: 13 Августа 2026 (proto v0.3.9)

Новый модуль — **USDT-стейкинг**: партнёр вкладывает USDT в депозит, получает 12 выплат
дохода по одной каждые 30 суток, а каждый прирост тела раздаёт реферальные бонусы вверх
по спонсорскому дереву в зависимости от **ранга** получателя.

> ✅ **Не breaking по wire-формату.** Всё добавленное — новые файлы плюс одно новое поле
> в существующем `oneof`. Старые клиенты его игнорируют, номера прежних полей не тронуты.
>
> ⚠️ **Source-breaking для Rust-потребителей `Ledger.Owner`**: в `oneof entity` появился
> новый вариант, поэтому исчерпывающие `match` по нему перестанут компилироваться, пока
> не обработают `StakingDepositId`. В `core` это уже сделано.

## 1. 💰 `biconom/types/staking.proto` — модели модуля

Новый файл с пространством имён `Staking`. Основные сообщения:

| Сообщение | Назначение |
|---|---|
| `Deposit` | Депозит: тело, расписание циклов, два флага реинвеста, статус |
| `DepositsSummary` | Агрегаты по всем депозитам партнёра |
| `Tier` | Ступень собственной доходности |
| `Rank` | Ступень карьерной лестницы: доля в раздаче + бонус за достижение |
| `RankProgress` | Текущий ранг, требования следующего, разбивка по веткам, история достижений |
| `Leg` | Вклад одной ветки первой линии с раскрытием, почему засчиталось столько |
| `Obligation` | Обязательство выплатить бонус за ранг |
| `Event` | Журнал: шесть видов событий по своим депозитам |
| `State` | Полное состояние партнёра одним ответом |
| `Config` / `Settings` | Захардкоженная экономика + изменяемые админом настройки |
| `Summary` | Сводка по модулю для админки |

### Два процента, которые нельзя путать

В модуле две независимые шкалы, и объединить их в одну таблицу нельзя:

| | **Тир** (`Staking.Tier`) | **Ранг** (`Staking.Rank`) |
|---|---|---|
| Что даёт | доход **со своих** денег | долю в раздаче **с чужих** депозитов |
| От чего зависит | сумма активных депозитов **сейчас** | вклад и оборот **за всё время** |
| Динамика | плавает вверх и вниз | **никогда не понижается** |

Партнёр может одновременно иметь ранг 12 (`"0.16"` с чужих депозитов) и тир `"0.05"`
(минимальная ставка со своих), если ранг взят давно командным оборотом.

### Соглашения о величинах

- **Деньги** — строками, как балансы `Ledger`.
- **Ставки** — тоже строками, но **коэффициентом**: `5%` → `"0.05"`, `16%` → `"0.16"`.
  Умножается на тело напрямую (`выплата = тело × rate`), поэтому ни клиент, ни сервер
  не делят на 100 и не гадают о масштабе. Целочисленное «× 10 000» здесь намеренно
  не используется: ошибка на порядок в таком представлении не видна глазом.

## 2. 🧾 `Ledger.Owner.staking_deposit_id` — новый владелец счёта

```protobuf
message Owner {
    oneof entity {
        uint32 org_pool_id = 1;
        uint32 wallet_id = 2;
        uint32 payment_network_id = 3;
        uint32 exchange_id = 4;
        // НОВОЕ
        uint32 staking_deposit_id = 5;
    }
}
```

Каждый депозит владеет **собственным счётом-леджером**: баланс этого счёта **и есть тело**
депозита — отдельного поля с телом в модели нет, двойной учёт исключён по построению.

Флаги счёта — `ALLOW_DEBIT | ALLOW_CREDIT` **без** `ALLOW_NEGATIVE`: счёт депозита это
реальное обязательство перед партнёром, уйти в минус он не может.

## 3. 📱 `biconom/client/staking/staking.proto` — клиентский сервис

9 методов. Главный — `GetState`: **всё состояние одним запросом** (настройки, сводка,
депозиты, ранг, бонусы), чтобы экран не делал три вызова.

| RPC | Назначение |
|---|---|
| `GetState` | Всё состояние; флаг `include_closed_deposits` влияет **только** на список депозитов, сводка всегда по всем |
| `GetConfig` | Статичная экономика — забирается один раз и кэшируется |
| `GetDeposit` | Карточка депозита |
| `CreateDeposit` | Создание; `idempotency_key` защищает от двойного тапа |
| `SetAutoReinvestProfit` | Реинвест прибыли: включение мгновенное, отключение — после ближайшей выплаты |
| `SetReinvestDeposit` | Переоткрывать ли тело новым депозитом при закрытии |
| `ListEvents` / `ListDepositEvents` | Журнал, курсорная пагинация |
| `GetRankProgress` | Детальный разбор ранга с разбивкой по веткам |

Разбивка по веткам (`legs`) намеренно **не входит** в `GetState`: у крупного лидера их
сотни, и главный экран стал бы самым тяжёлым именно у самых ценных партнёров.

## 4. 🛠 `biconom/admin/staking/staking.proto` — админский сервис

13 методов под одним правом `ADMIN_STAKING`.

- `GetState(distributor_id)` — состояние любого партнёра одним запросом;
- `GetRankProgress` — разбор «почему не взял ранг»: видно, у какой ветки сработал лимит;
- `ListObligations` / `ReleaseObligation` — ручная модерация бонусов за ранг,
  фильтры по факту выплаты, рангу и партнёру, поштучная реализация;
- `ListRankBonusSettings` / `SetRankBonusAutoRelease` — автовыплата **отдельно
  для каждого ранга**, действует только на будущие достижения;
- `UpdateSettings` — минимальная сумма входа, дефолты реинвеста, статус приёма депозитов.
