## 1. 🏅 `Staking.Leg.current_rank`

### `biconom/types/staking.proto`

```protobuf
message Leg {
    // ...поля 1–10 без изменений...

    // Текущий ранг лидера ветки. 0 — квалификации нет. Та же величина, что
    // `RankProgress.current_rank` у самого лидера; доля лестницы и требования
    // ранга — в `Config.ranks` по этому номеру, вторым источником не дублируются.
    uint32 current_rank = 11;
}
```

### Где приходит

`client/staking/StakingService/GetRankProgress` и
`admin/staking/StakingService/GetRankProgress` — везде, где есть `legs`.
В `GetState` блок `rank` по-прежнему без `legs`.

### Как показывать

| `current_rank` | Карточка ветки |
|---|---|
| `≥ 1` | «`{current_rank}` Rank · `{ranks[current_rank].referral_rate}` %» — процент из `GetConfig`, тот же справочник, что для шапки |
| `0` | строку ранга не показывать (лидер ветки ещё не квалифицирован) |

Отдельного поля с процентом в `Leg` нет намеренно: таблица рангов уже приходит
в `GetConfig`, и второй источник того же числа разошёлся бы с первым.

## 2. 🪙 Матчинг-бонус: «токен упущенной выгоды» сквозным (поведение, без изменения схемы)

Раньше спонсор, которому по лимиту депозита не причиталось ничего
(`payout = 0`), не получал проводки — и карточки `splitMatchingBonus` с его
`missed_amount` в истории транзакций у него не было (только в
`GetMatchingBonusHistory`).

Теперь такой спонсор — **если он участвует в пуле** (`sponsor_deposit_at_pay > 0`)
— получает **`0.000001 USDT`** со счёта компании, и в истории у него появляется
обычная карточка `splitMatchingBonus`. Механика один в один как у токена
реферальной лестницы стейкинга (`stakingReferral`, 27.08).

| Поле | Токен | Обычная выплата |
|---|---|---|
| `amount` | `"0.000001"` | доля по лимиту |
| `splitMatchingBonus.missedAmount` | сколько прошло выше | то же |
| `splitMatchingBonus.targetLimit` | лимит спонсора (уже выбран нижними) | то же |

Спонсорам **без депозита** в пуле токен не начисляется — их записи по-прежнему
видны только в `GetMatchingBonusHistory`.

Уведомление `bonus_received` (push / Telegram) для матчинга теперь несёт строку
«Прошло выше по структуре: X USDT» — у всех получателей, у кого `missed_amount > 0`.

Фронту делать ничего не нужно; стоит только проверить, что карточка с суммой
`0.000001` не отображается как «0.00».

## 3. 🏟 Арена 5 `staking` — активность в стейкинге (без изменения схемы)

В `ListArenas` / `GetArena` появляется пятая арена. Схема прежняя, изменились
только комментарии в `biconom/types/arena.proto` (`Arena.Id.id` — «1..5», список
имён дополнен `staking`).

| Поле | Значение |
|---|---|
| `arena.id` | `5` |
| `arena.name` | `"staking"` |
| `arena.total_cycles` | `0` до запуска |
| `card.cycle` | `null` до запуска — как и описано у `Arena.Card.cycle` |

**Баллы** — как у арены 1 (покупка WINZU): каждый прирост тела депозита стейкинга
(открытие, подарок без блокировки маркетинга, реинвест тела, реинвест прибыли)
даёт `amount` баллов вкладчику **и столько же его прямому спонсору**. Итог
партнёра за цикл — личный объём плюс объём первой линии. Единица — USDT,
`value_precision = 6`: `"100.000000"` = 100 USDT. Депозиты с блокировкой
маркетинга баллов не дают.

**Запуск отдельным решением.** Арена только зарегистрирована; цикл стартует
админ через `ArenaAdminService.StartCycle{arena_id: {id: 5}}` (шаблон —
`UpdateTemplate`). Пока цикла нет, очки не копятся; ретро по уже открытым
депозитам не будет — счёт идёт с момента старта.

Фронту: карточку арены 5 рендерить теми же компонентами; состояние
«циклов ещё не было» (`cycle = null`, `total_cycles = 0`) уже предусмотрено
контрактом и должно отображаться как «скоро».
