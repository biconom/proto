# 2026-11-04 — proto 0.3.36 (core 1.10.52)

## «Мои линии»: глубина выплат, награда и свежие новички — в `GetSlotV2`

`biconom.types.MarketingSlotV2` (ответ `MarketingService/GetSlotV2`):

| Поле | Что значит |
|---|---|
| `uint32 payout_depth_max = 11` | до какого уровня включительно владелец view-слота сейчас получает награды (1..7) |
| `uint32 qualified_first_line_count = 12` | активные личники владельца в этом дереве; `payout_depth_max = min(count + 1, 7)` |
| `LevelState.repeated Price rewards = 7` | награда за одного партнёра уровня за активацию его ваучера (из плана дерева) |
| `LevelState.repeated uint32 recent_slot_ids = 8` | до 3 слотов уровня с самой свежей первой активацией лицензии, новые первыми |

Уровень с `level > payout_depth_max` — «не зарабатывает» (перечёркнутая иконка).
«Заработано» на таком уровне может быть ненулевым: это доход прошлых периодов.

Подробности слотов из `recent_slot_ids` — в `slots`, их дистрибьюторы — в `distributors`,
аккаунты (аватар, имя) — в `accounts`. Списки дедуплицированы; **ищите по id**, не по
позиции: раньше там было ровно два элемента (executor и view), теперь больше.
`slot_states` и `distributor_states` по-прежнему только для executor и view.

## Шапка «Спонсоры» — в том же `GetSlotV2`

| Поле | Что значит |
|---|---|
| `repeated uint32 upline_slot_ids = 13` | до 3 вышестоящих view-слота на пути к слоту executor (включительно), ближайшие первыми |
| `uint32 upline_count = 14` | сколько всего слотов на этом пути (= разница уровней) |

- Левый блок — `upline_slot_ids[0]` (прямой вышестоящий).
- Правый блок — аватары `upline_slot_ids`, «+N» = `upline_count − upline_slot_ids.len()`.
- Выше своего слота цепочка не идёт. При просмотре своего слота или слота не из своей
  структуры оба поля пустые. Подробности слотов — в `slots` / `distributors` / `accounts`.

## Экран «цепочка до слота» (Below you) — уже есть, `GetSlotBreadcrumbs`

Новый метод не нужен: экран со списком «You → промежуточные слоты → Target slot»
строится на существующем `MarketingService/GetSlotBreadcrumbs` (запрос — тот же
`biconom.types.Slot.Id`, что у `GetSlotV2`, например `{"id": <slot_id>}`).

- **Права.** Слот должен быть в вашей слотовой структуре (ниже вашего слота в том же
  дереве), иначе ошибка `SLOT_VIEW_PERMISSION_DENIED`. Дерево берётся у запрошенного
  слота, ваш слот ищется в нём же.
- **Строки сверху вниз** — `chain_ids`: `[0]` — ваш слот («You»), последний — запрошенный
  («Target slot»), между ними все промежуточные, без ограничения по количеству. Свой слот
  запросили — в списке ровно один элемент.
- **Данные строки** — как везде, по id: `slots[]` (по `chain_ids`) → `slots[].distributor_id`
  → `distributors[]` → `distributors[].account_id` → `accounts[]` (имя, аватар). Списки
  дедуплицированы: у одного дистрибьютора может быть несколько слотов в цепочке —
  запись дистрибьютора придёт одна, ищите по id, не по позиции.
- **Метка справа** — `distributors[].relationship_state`: **реферальная** связь владельца
  слота с вами (не слотовая; слотовая — в `slots[].relationship_state`, для этого экрана
  не нужна).

| `relationship_state.kind` | `level_diff` | Метка |
|---|---|---|
| `PERSONAL` | — | You (ваш же слот) |
| `TEAM` | 1 | First Line |
| `TEAM` | N ≥ 2 | Team: N line |
| `UPLINE` / `NONE` | — | Not in team |
